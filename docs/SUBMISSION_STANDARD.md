# Submission standard

Coursework files must make sense independently to the instructor. Include the assignment content, accurate project assumptions, required names and legitimate academic citations. Avoid references to the repository, internal notes, previous chats, other local documents, preparation steps, assistant prompts, missing-material reminders or generated-file descriptions.

Keep instructions, provenance, validation, evidence gaps and handoff notes in docs/. Speaker notes, document properties, hidden comments, tracked changes, embedded relationships and ZIP member names are part of the release review. Clear irrelevant authoring-tool boilerplate and personal paths; never claim false authorship or remove a required disclosure.

Package using an explicit list of files. Do not include README, AGENTS, checklists, manifests, build scripts, caches, obsolete versions, software keys or the course installation guide. Preserve original human evidence unchanged in references/; include it only when the assignment needs it. Do not fabricate evidence to satisfy a missing input.

Run the release checker, inspect every changed document page and slide, and open the schedule in the native application. Record what was actually checked and any remaining limitations in docs/VALIDATION.md. Keep local release completion, LMS submission, grading and instructor approval as separate states.
